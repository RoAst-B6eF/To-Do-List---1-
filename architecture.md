## 1. Что это за проект

Веб-приложение «To-Do List & Focus Timer» — задачник с автоматическими приоритетами по дедлайну,
Pomodoro-таймером (Focus) и (в будущем) синхронизацией с Google Calendar. Интерфейс полностью на русском.

Путь к коду: `C:\Users\mihaz\OneDrive\Рабочий стол\CLaude_code\todo-focus`

Текущая стадия: **frontend-прототип на моках**. Бэкенда нет, все данные хранятся в `localStorage`
через React Context. Бэкенд-стек ниже зафиксирован как план, но не реализован ни на процент.

## 2. Стек

### Реализовано (frontend)
- Next.js 14 (App Router) + TypeScript
- Tailwind CSS + shadcn/ui (частично — сгенерены только нужные примитивы, см. §4)
- Framer Motion — анимации списка задач
- Recharts — недельный bar-chart в Focus
- next-themes — тёмная/светлая тема (dark по умолчанию)
- lucide-react — иконки
- Состояние: React Context (`src/lib/store.tsx`) + `localStorage` (ключ `todo-focus-state-v1`)

### Запланировано, НЕ реализовано
- Backend: NestJS + Prisma + PostgreSQL
- Авторизация: JWT (email/пароль, хэширование argon2)
- Google Calendar API — двусторонняя синхронизация, OAuth2, refresh-token на пользователя

## 3. UI-стиль

Минимализм: `rounded-xl`, `shadow-sm`, тёмная тема по умолчанию. Переключатель темы в шапке (`theme-toggle.tsx`).

## 5. Модель данных (`src/lib/types.ts`)

```ts
Task {
  id, title, description?, deadline (ISO), status: "active"|"completed",
  createdAt, completedAt?,
  focusMinutes?: number        // накопленное время фокуса, привязанное к этой задаче
}

FocusCategory { id, name, color (hex) }

WeeklyFocus = Record<weekday "Пн".."Вс", Record<categoryId, minutes>>
  // фиксированные 7 слотов, перезаписываются из недели в неделю — НЕ история по датам

DailyFocus = Record<"YYYY-MM-DD", minutes>
  // реальная дата-ключ, копится бессрочно — источник для streak/heatmap (см. §7)

FocusSettings {
  workMin, shortBreakMin, longBreakMin, roundsUntilLongBreak,
  soundEnabled, notifyOnSessionEnd,
  dailySummaryEnabled, dailySummaryHour (0-23)
}
```

Всё персистится одним JSON-блобом в `localStorage["todo-focus-state-v1"]`:
`{ tasks, categories, weekly, settings, dailyFocus, lastSummaryDate }`.

## 6. Логика авто-приоритета (`src/lib/priority.ts`)

Взаимоисключающие категории, считаются на лету из дедлайна (`getDaysLeft`):
- ⚫ **Просрочено** (`daysLeft < 0`) — `bg-rose-900`, пульсирует (`animate-pulse`)
- 🔴 **Красный** (`≤ 3` дн) · 🟡 **Жёлтый** (`≤ 5`) · 🟢 **Зелёный** (`≤ 7`) · ⚪ **Серый** (`> 7`)
- Флаг **«Горит»** (`0 ≤ daysLeft ≤ 2`) — отдельный независимый бейдж/фильтр, статичный (не пульсирует)

Sidebar: Поиск · Все задачи · Сегодня · Горит · По важности (5 категорий, счётчики живые).
Выполненные задачи остаются внизу списка «Все задачи» (зачёркнуты), чекбокс возвращает в активные.

## 7. Хронология изменений в этой рабочей сессии

### Этап A — Focus: доработка (реализовано и проверено в preview)
Исходный запрос: 4 фичи для Focus.
1. **Настраиваемые длительности** — `FocusSettings.workMin/shortBreakMin/longBreakMin/roundsUntilLongBreak`,
   применяются мгновенно через `useMemo`-derived `durations`, если таймер не запущен — секунды подхватывают новое значение.
2. **Звук + браузерное уведомление по окончании сессии** — `playBeep()` (чистый Web Audio API,
   двойной синус-сигнал, без файлов-ассетов) + `Notification` API. Триггерятся **только при естественном
   завершении** таймера (когда `secondsLeft` дошёл до 0), НЕ при ручном «Пропустить» —
   осознанное решение, чтобы ручной skip не был навязчивым (звук на каждый клик раздражал бы).
3. **Привязка Pomodoro-сессии к задаче** — `<select>` со списком активных задач в `focus-timer.tsx`,
   `logFocus(categoryId, minutes, taskId?)` в сторе увеличивает `Task.focusMinutes`. Отображается
   бейджем `⏱ N мин` в `task-item.tsx` и строкой «🍅 В фокусе на этой задаче: N мин» в `task-dialog.tsx`.
4. **Ежедневные уведомления об итогах дня** — `DailyFocus` карта по датам в сторе, компонент
   `focus-daily-notifier.tsx` раз в минуту проверяет: если `dailySummaryEnabled` и текущий час
   `>= dailySummaryHour` и сегодня ещё не уведомляли (`lastSummaryDate`) — шлёт `Notification` с
   суммой минут за день, помечает `markSummaryNotified()`.

Настройки редактируются в новом `focus-settings-dialog.tsx` (Dialog из shadcn, без внешних select/switch
компонентов — использованы нативные `<input type="checkbox">`/`<input type="number">`, т.к. в проекте
не сгенерены shadcn `select`/`switch`/`popover`).

### Этап B — баг-фикс недельного графика (реализовано и проверено)
**Симптом:** на оси Y графика «Статистика за неделю» все подписи выглядели как «0м», хотя данные
за неделю были корректны (тултип при наведении показывал верные суммы).

**Причина:** в `weekly-chart.tsx` был `margin={{ left: -18 }}` у `<BarChart>`. Подписи оси Y
выровнены по правому краю (`text-anchor="end"`), поэтому при таком отрицательном отступе многозначные
числа («160м», «120м» и т.д.) уводили свои ведущие цифры за пределы видимой области SVG (x < 0),
и обрезались — визуально оставалось только «0м» от любого числа. DOM/данные были верны всегда,
баг был чисто рендер-визуальный. **Фикс:** `margin.left` изменён с `-18` на `0`. Подтверждено скриншотами
до/после через preview-тулинг.

Диагностика заняла много шагов (проверка DOM textContent, computed styles, ручной re-render SVG→canvas
в 3x масштабе) — стоит помнить на будущее: если ось графика показывает подозрительно одинаковые/усечённые
подписи при **верных** данных в DOM — в первую очередь проверять `margin.left`/`text-anchor`/ширину
области под подписи, а не логику данных.

### Этап C — редизайн профиля: РЕАЛИЗОВАНО И ПРОВЕРЕНО В PREVIEW

Был: слишком сухой `/profile` — только 4 карточки-счётчика (Выполнено/Активные/Горит/Просрочено).
План собран через серию вопросов пользователю (11 вопросов, все отвечены), реализован по команде «ДЕЛАЙ»:

**Реализовано:**
1. **Персонализация** — редактируемое текстовое имя пользователя (БЕЗ аватара), приветствие сверху.
   Хранить как новое поле в сторе (например `profileName: string` + `setProfileName()`), персистить
   вместе с остальным состоянием.
2. **Streak** — яркий блок «🔥 Серия: N дней подряд с фокус-сессией». Считается из `DailyFocus`
   (подряд идущие даты с `minutes > 0`, заканчивая сегодня или вчера — сегодняшний день не должен
   обнулять серию, если человек ещё не фокусировался).
3. **Достижения** — сетка из 6-8 бейджей с прогрессом, например: первая выполненная задача,
   100/500 минут в фокусе всего, серия 3/7 дней, ноль просроченных задач, 10 выполненных задач.
   Разблокированные визуально отличаются от заблокированных.
4. **Heatmap-календарь** — сетка квадратиков по дням (как контрибуции GitHub) за последние ~12 недель,
   яркость/цвет = минуты фокуса в этот день. Источник данных — `DailyFocus`.
5. **Рекорд «Лучший день»** — дата + количество минут максимального дня из `DailyFocus`.
6. Существующие 4 карточки статуса задач — остаются без изmenений.

**Осознанно исключено** (спросили — отказались): donut-диаграмма по категориям, список топ-3 задач
по времени фокуса, сравнение этой недели с прошлой (%), мотивационная цитата/совет дня, система
уровней/XP от общего времени фокуса.

**Что сделано технически:**
- `seedDailyFocus()` в `mock-data.ts` — 84 дня истории (~35% дней без фокуса для правдоподобия),
  гарантированная серия последних 5 дней перед сегодня (чтобы streak не был нулевым на свежем
  демо-старте) и один рекордный день (240 мин, 20 дней назад). `seedProfileName()` — дефолтное имя.
- `lib/focus-stats.ts` — `getFocusStreak()`, `getBestDay()`, `getHeatmapWeeks()` (выравнивание по
  неделям Пн-Вс, `weeks=12` по умолчанию).
- `lib/achievements.ts` — `computeAchievements(tasks, dailyFocus)` → 7 бейджей с `unlocked` +
  опциональным `progress {current, target}`.
- `components/focus-heatmap.tsx` — сетка 12×7, 5 уровней интенсивности (indigo), легенда снизу,
  `title`-тултип с датой и минутами на каждом квадратике.
- `components/achievements-grid.tsx` — карточки бейджей, разблокированные подсвечены indigo-рамкой,
  у заблокированных с `progress` — прогресс-бар.
- `store.tsx` — добавлены `profileName` + `setProfileName`, наружу отдаётся сырая `dailyFocus` карта
  (раньше был доступен только производный `todayFocusMinutes`); всё персистится в том же JSON-блобе.
- `profile/page.tsx` — приветствие с инлайн-редактируемым именем (`<Input>` без рамки внутри
  заголовка), карточки streak и «лучший день» сверху, затем существующие 4 карточки статуса,
  затем heatmap и достижения.

**Проверено в preview:** свежий `localStorage` (без него — seed данные подхватываются и стрик/
рекорд/heatmap не нулевые), редактирование имени сохраняется после `reload`, достижения корректно
разблокируются/блокируются по реальным данным (например «Всё под контролем» заблокировано, т.к.
в сид-задачах есть одна просроченная).

Статус: **готово.**

## 8. Известные особенности среды разработки

- **Preview-тулинг и порт 3000**: если в другом чате/вкладке уже запущен dev-сервер на этой же
  папке проекта, `preview_start` в текущей сессии выдаёт ошибку занятости порта 3000 и не
  переключается на другой порт автоматически, несмотря на `autoPort: true` в `.claude/launch.json`
  — реальный обходной путь: попросить пользователя закрыть тот, другой, сервер, и повторить попытку.
- Скриншоты preview зависают/не открываются корректно при открытом Radix-диалоге в некоторых
  случаях (артефакт headless-рендерера, не баг приложения).
- `npm run build` — актуальный способ проверки типов и ESLint перед тем, как считать фичу готовой;
  использовался после каждого крупного изменения в этой сессии, проходит чисто (0 ошибок, 0 warning).

   через preview-тулинг (см. особенности в §8).
